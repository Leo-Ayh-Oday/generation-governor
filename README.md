# generation-governor

一个流治理器：**只有当传输真的停了，才把许可交给下一个请求。**

它不是"检测错误然后再试一次"的组件，而是一个把"结束"和"结束的声明"拆开的东西。

---

## 问题

Agent 运行时里有一句最难证伪的声明：**"任务完成了。"**

它下面还压着一层更隐蔽的：**"这条流结束了。"**

这两件事经常被当成同一件。一次 LLM 调用返回 `done`，看起来流到头了，于是并发额度被释放、下一个请求放行、账目标记完成。但如果下层传输还握着连接呢？如果 adapter 在异常路径上把"我出错了"包装成了一个正常结束呢？

一个包装器告诉你它结束了，你凭什么信？

这个仓库给出的是：**不信。** 只有在拿到可信的终局事实、或者传输自己给出的静默证据时，才释放。

```ts
// 结束 ≠ 停止
if (chunk.type === 'finish' && (chunk.reason.kind === 'error' || chunk.reason.kind === 'aborted')) {
  // 这一条流的"结束"不是"完成"的证据
  // 不得据此确立 transport quiescence
}
```

## 为什么这个仓库值得读：五轮

这套东西的核心不是那份治理器，是它被审出来的过程。

我给它配了独立的复核者——一个只读、只攻击、不给面子的角色。然后连续五轮，**每一轮都抓到一个"声明说管住了、实际没管住"的地方**，而且每一轮换一张脸：

| 轮次 | 缺陷是怎么活下来的 | 复核者给的裁决 |
|---|---|---|
| 1 | 测试**把缺陷写成了断言**：一条用例直接断言"普通流错误也能确认静止" | REVISE |
| 2 | 篡改矩阵 19/19 全绿，**少了 `[]` 那一条**（`[].every(...)` 恒为真） | BLOCKED |
| 3 | 校验器只校验"所列文件"，**没有代码自有的期望集合**，删一个证据文件再重封即通过 | BLOCKED |
| 4 | handoff 声明"14 个角色全部绑定"，**实际只有 2 个**，其余 12 个只有形状检查 | REVISE |
| 5 | 覆盖表改成"由代码生成"了，但等级是**常量字面量**——它证明"角色在列表里"，不是"角色被检查过" | REVISE |

第 5 轮是这套流程第一次自己抓到自己的方法论：

> 在仓库外复制一份代码，注入一行 `if (role === 'selfcheck/budget-0') continue`，让绑定静默少做一个角色。
>
> `print-coverage` 仍然打印 `14/14 count-bound`。
> 校验器仍然 `RC=0`。
> 连 calibration digest 都和正确实现完全一致。
>
> **一个已经不再检查该角色的校验器，和正确的校验器，在事后留存的所有记录里长得一模一样。**

这不是"又一个 bug"。这是**仪表盘的指针被焊死在 100 码**——表是对的，但它证明的东西比它看起来少一层。

复核报告原文在 `docs/audit/`，逐条 `CONFIRMED / REFUTED / UNPROVEN`，包括我自己被打回的部分。

## 从这五轮里提炼的两条方法

### 1. 先红后绿，而且必须是同一份伪造

改完之后跑绿，什么都证明不了。证据必须长这样：

```
## variant: omission-full - RED (base f22141eb4c)
[probe] repo=... head=f22141eb4c dirty=0
[probe] variant=omission-full resealed: 13 files, 2 records; manifest=ea39c6fbc19e
[validate] chain verified ... RC=0

## variant: omission-full - GREEN (9a5aea9bd6)
[probe] variant=omission-full resealed: 13 files, 2 records; manifest=ea39c6fbc19e
[validate] frozen evidence manifest carries no frozen journal for the required role wire
[probe] variant=omission-full RC=1
```

**两相的 manifest 摘要逐字相同**，证明红相和绿相跑的是同一份伪造，只是换了校验器。没有这一行，"红了又绿了"可以有一百种解释，其中九十种是骗自己。

红相必须在**未修改的实现**上跑，且工作树必须是干净的。

### 2. 声明类机制必须自带负校准

任何"已覆盖 / 已绑定 / 已关闭"的声明，必须来自**观测记录**，不能来自角色列表、类型字面量或常量。

每个这类机制都要配一个负校准：**故意让机制自身失效，校验必须判负。** 校准跑不通，等于机制不存在。

这条规则的来历：前四轮的缺陷形态各不相同，病根却是同一个——**"我说我管住了"和"我真的管住了"之间没有强制连接。**

## 不变量

治理器围绕一条不变量运转：

> 释放许可需要**可信的下层终局事实**，或**传输自己给出的静默证据**；两者都没有，就不可逆地停止：保留屏障、拒绝排队与后续请求、记录 unknown。

具体到实现：

- `finish.reason.kind ∈ {stop, tool-calls, max-tokens}` 且观测到 finish → 可信终局
- `kind ∈ {error, aborted}` → **不构成**静止证据
- 未观测到 finish → 一律 unknown（不存在"合法地不产生 finish"的通道）
- 等待 `next()` 有界；超时记 unknown，**绝不当 completed**
- 停止不可逆，没有复位入口；停止之后不再签发任何许可

代价是真实的：**瞬时 provider 错误会让整个 run 停下，不再重试。** 这是有意为之——真实链路里不传传输探针时，释放屏障没有任何合法依据。为了保留重试而开口子，等于把伪造静止请回来，只是这次有个说得过去的借口。

要恢复重试，必须先有一个 **transport-owned probe**（本地端点自己的活动连接计数，或 adapter 暴露的真实终止事件），不许用自洽伪造顶替。

## 边界：这个仓库没有证明什么

写在这里，不是免责声明，是这个项目的一部分。

- **本地检查挡不住全量重算的伪造者。** 一个愿意把记录、manifest、链、journal 全部重新推导到自洽的人，任何本地校验都分不出来——摘要算法是公开的，期望值就在仓库里。要闭合这一层，需要外部锚（签名的 checkpoint、已发布的 SHA、或第三方时间戳）。
- **进程退出仍无界。** 释放屏障不等于进程结束；底层 socket 持有句柄时，仍依赖 runner 的外部超时。
- **没有接真实 provider。** 所有验证都跑在 fake transport 和本地端点上，不存在 live 调用。
- **第 6 轮还没做完。** 覆盖等级正在从"常量"改成"观测记录"，结果未出。
- **这不是一个通用 agent 框架。** 它只做一件事：不许把"结束的声明"当成"结束的事实"。

## 出身

这是 `scripts/arcp-r6-go41-governor.ts` 在 `ebea03253b` 处的一份可独立运行的快照。

- **正交源**在私有宿主仓库的 `scripts/` 下；这里的副本不是它的替代品。
- **为什么要抄一份**：宿主仓库里的脚本依赖它自己的包类型（`@deepseek-ai/dsh-llm`），脱离那个 monorepo 就跑不起来。这里把那份类型依赖换成本地的 `src/types.ts`（116 行），于是 34 个测试可以在任何一台装了 Node 的机器上跑。
- **漂移风险**：两份代码会分叉。分叉不是意外，是这个仓库的已知代价——它存在的目的是"能独立证明"，不是"成为主实现"。

宿主运行时的其余部分不在这个仓库里——这里只有能独立跑、能独立判断的那部分。
